# Kitty 电子宠物 · 产品说明书

> 面向使用者。想知道怎么实现，看 [`pet-design.md`](pet-design.md)。
> 本文列出她的**全部功能**，并标注每一项当前的实现状态。

状态标记：

| 标记 | 含义 |
| --- | --- |
| ✅ 已有 | 当前固件已经能用 |
| 🚧 待接入 | 软件能做，还没做 |
| 🎨 待素材 | 卡在美术/音效素材，不是卡在代码 |
| ⏳ 待实测 | 功能已有，数值要真机测 |
| 🧩 用法 | 设备不用改，agent 自己就能做 |
| ❌ 不做 | 设计上明确排除 |

> **当前进度**：V0–V3 的设备端功能都已落地 —— 四项数值、呼吸眨眼、夜间陪伴（真猫呼噜）、
> 唤醒词、agent 协议、配网页。剩下的 🚧 都是**表达细化**（饿的时候主动叫、凑近看你、
> 眼皮沉这类），不是缺功能；另有几处**明确不做**的（三击、长按菜单、主动事件），
> 各自章节里写了理由。

---

## 1. 她是什么

一台放在桌上的 Kitty。她有自己的作息、情绪和体力，会困、会饿、会自己找你。

**不需要网络、不需要账号、不需要激活**。拔掉网线、云端服务下线、公司跑路，她都照常活着。

插上电脑，她可以变成你电脑上 AI agent 的"身体"——agent 在她脸上做表情，用她的嗓子说话，
而她干活会累，需要你去喂、去摸、去让她睡。

到了晚上，她安静下来陪你睡。

她的身体状态，是你和 agent 一起经营出来的。

## 2. 规格

| 项 | 参数 |
| --- | --- |
| 主控 | ESP32-S3R8，8 MB PSRAM |
| 屏幕 | 0.85 英寸，128×128，IPS |
| 声音 | 单麦克风 + 单喇叭（ES8311 + NS4150B） |
| 灯 | 1 颗 RGB 灯珠 |
| 按键 | 1 颗可用（BOOT）；另一颗 POWER 是电源开关，按一下断电 |
| 触摸 | 无 |
| 摄像头 | 无 |
| 姿态感应 | 无（不能摇晃，不能翻转识别） |
| 网络 | 仅配网用的临时热点；不联网 |
| 供电 | USB（没有电池，拔掉电源即关机） |

## 3. 开机与第一次使用

### 开箱到能用（约 5 分钟）

| 步骤 | 做什么 | 你会看到 | 状态 |
| --- | --- | --- | --- |
| 1 | USB 线插电脑或充电器 | 开机动画，宠物脸出现 | ✅ 已有 |
| 2 | 等她几秒，让她醒过来 | 眨眼、打量四周 | ✅ 已有 |
| 3 | 长按 BOOT 3 秒进配网 | 屏幕盖上一块小黑板，写着热点名和 192.168.4.1 | ✅ 已有 |
| 4 | 手机连热点（密码 kitty1234），打开 192.168.4.1 | 一组参数表单 | ✅ 已有 |
| 5 | **至少设置时间** | 保存后热点自己关掉，回到宠物画面 | ✅ 已有 |
| 6 | 留着插电 | 开始过她自己的日子 | ✅ 已有 |

> **时间必须设。** 她靠时间判断早晚、决定什么时候睡。没有时间，夜间模式不会启动，
> 其余功能不受影响。

### 头十分钟建议这么玩

1. 摸摸头（BOOT 短按），看她怎么回应
2. 叫她的名字，看她抬不抬头
3. 喂一口（BOOT 双击），看她吃不吃
4. 等着，别理她两分钟——看她会不会自己找点事做

## 4. 屏幕上会看到什么

整块 128×128 的屏幕**只有她的脸**。没有状态栏、没有文字、没有图标、没有进度条。

这是刻意的设计：一块 0.85 寸的屏，塞进数字和文字就不像宠物，像仪表盘。

### 她不显示数字

| 你关心的 | 她怎么告诉你 | 状态 |
| --- | --- | --- |
| 饿不饿 | 表情发蔫、主动叫、盯着你看 | 🚧 待接入（发蔫和灯色已有，主动叫、视线没有） |
| 累不累 | 动作变慢、频繁打哈欠、眼皮沉 | 🚧 待接入（变慢和哈欠已有，眼皮沉缺素材） |
| 脏不脏 | 毛发帧变化、灯色变暗 | 🎨 待素材（灯色变暗已有，掉毛帧要新美术） |
| 喜不喜欢你 | 主动凑近（高）／躲开视线（低） | 🚧 待接入（整脸平移的能力已具备） |

**要精确数值，插电脑让 agent 读。** 说明书不给她加数值界面，是因为看得见的数字会让人
盯着数字玩，而不是看着她。

### 会短暂盖住脸的东西

都极简、都会自动消失：

- 配网时的热点名与地址（黑底两行小字，仅配网期间，✅ 已有）
- 被 agent 接管的指示：**不盖脸**，改用灯 4 Hz 快闪（✅ 已有）

## 5. 三种身份

她始终处在三种身份之一，切换是自动的。

| 身份 | 什么时候 | 她会做什么 |
| --- | --- | --- |
| **自主** ✅ 已有 | 默认状态 | 自己过日子：张望、犯困、打哈欠、望着你；数值照常衰减 |
| **插电** ✅ 已有 | 插上 USB，但电脑没接管 | 慢慢回精力，别的衰减变慢 |
| **被接管** ✅ 已有 | 电脑上的 agent 主动连接并握手 | 表情交给 agent 指挥；你摸她的动作会转告 agent；3 秒没心跳就交还 |

> **插电不等于被接管。** 插充电宝、插充电器，她只是插着电待机；只有电脑上的 agent
> 明确连上来，才会交出控制权。

## 6. 她会做的表情与动作

| 功能 | 说明 | 状态 |
| --- | --- | --- |
| 全屏宠物脸 | 57 帧动画，9 组情绪，铺满整块屏 | ✅ 已有 |
| 呼吸起伏 | 静止时身体轻微起伏，不是一张死图 | ✅ 已有 |
| 眨眼 | **美术自身带的**（idle/wait/run 三组里有闭眼帧），不是代码硬压的 | ✅ 已有 |
| 情绪表情 | 九组动作 + 速度 + 灯色组合出开心 / 蔫 / 困 / 睡 | ✅ 已有 |
| 抬头看人 | 被叫名字时抬头 | ✅ 部分（叫名字会抬头；"有人靠近"没有传感器） |
| 低数值表现 | 饿了发蔫、累了动作变慢、脏了灯变暗 | ✅ 部分（发蔫和变慢有，掉毛帧没有） |
| 暗色主题 | 夜间与默认两套配色 | ✅ 已有 |
| 侧边状态栏 | 脸挪到一侧，左侧竖条显示：红心（亲密度，按比例填充）、碗（饱食，同上）、USB 插头（插着电脑时亮）、电池轮廓、信号格（配网页热点开着时亮） | ✅ 已有 |

### 这些表情是怎么来的

- 一共 **57 帧**，分 **9 组动作**（各组帧数：6 / 8 / 8 / 4 / 5 / 8 / 6 / 6 / 6）
- 注意：这九组是**动作**（待机、转身、跑动、挥手、跳、蔫、张望、端详），不是九张不同的脸 ——
  素材里没有"生气脸""睡觉脸"这种东西。情绪是靠挑哪一组动作、多快、配什么灯来表达的
- 每帧 **88×128**，RGB565 格式，合计约 **1.28 MB**，直接编译进固件
- 面板是方的（128×128），画面旋转是在生成帧的时候做好的，不是屏幕上转
- 选哪一组：先看服务端（或本地情绪）判定，其次看设备状态

新增一组情绪就要重新算 Flash 预算，不是随手加一条。

## 7. 怎么跟她互动

**全身上下只有一颗能用按键。** 旁边那颗 POWER 是电源开关——按一下断电、再按一下上电，
她管不了它。所以日常操作全在这张表里。

| 操作 | 动作 | 状态 |
| --- | --- | --- |
| 单击 | 摸摸头（加亲密度），**四种反应随机**：喵+挥手 / 雀跃+跳 / 咕噜+端详 / 只是看着你 | ✅ 已有 |
| 双击 | 喂食（加饱食），咀嚼声 + 跳一下 | ✅ 已有 |
| 长按 3 秒 | 开 / 关配网热点（见 §14） | ✅ 已有 |
| 配网中单击 | 关掉热点，屏幕上的字一起消失 | ✅ 已有 |
| 叫她的名字 | 有反应（抬头/看过来/应一声） | ✅ 已有（链路已跑通；真人音量下识别率待确认） |
| 拍手 / 大声 | 吓一跳（转头看你 + 一声叹气） | ✅ 已有 |

### 为什么没有"长按菜单"

早期设计想用长按进一个极简菜单（配网 / 夜间 / 静音 / 音量三档 / 退出）。做之前评估了一下，
四个选项**都有别的路**，而菜单本身要在 128×128 上画界面、做单击切换/长按确认/5 秒超时的状态机：

| 菜单项 | 别的路 | 结论 |
| --- | --- | --- |
| 配网 | 就是现在的长按 | 菜单反而多一步 |
| 夜间模式 | 作息时间到、或 agent `pet.night` | 只有"没对时 + 没 agent"才真需要 |
| 静音 | 配网页音量拉到 0 | 同样要开热点，一样 |
| 音量三档 | 配网页 0–100 连续调 | 三档不如连续 |

所以**长按保持直接进配网**，菜单不做（记在设计文档的排除项里）。

### 按错了会怎样

规则是**宁可少做，不要做错**：

| 你按了 | 她理解成 |
| --- | --- |
| 想双击，第二下没跟上 | 一次摸头 |
| 长按没到 3 秒 | 一次单击（摸头） |
| 配网中误点一下 | 热点关掉，重新长按就好 |

喂食有上限，最坏结果是浪费一次动作，不会把她撑坏。

> **为什么没有三击**：这颗按钮的底层库在这块板子上分不出"连按三下"和"两次单击+一次双击"，
> 实测三下会被判成 `单击 / 单击 / 双击`。一个一半概率不生效的手势比没有更糟，所以去掉。
> 清洁和陪玩因此只有 agent 能触发。

## 8. 养成：四条数值

她身上有四条数值，都会随时间变化。**V0 已经把四条数值、衰减和掉电存档做出来了**，
下面这张表就是现在跑在设备里的规则（衰减速率见设计文档 §6）。

| 数值 | 会掉的原因 | 怎么补 | 掉了会怎样 |
| --- | --- | --- | --- |
| **饱食** | 时间流逝；agent 高强度干活 | 喂食 | 表情发蔫、动作变慢 |
| **精力** | 醒着的时间；**agent 每完成一次任务都扣** | 睡觉、插电 | 见底会强制睡着，叫不醒 |
| **清洁** | 时间流逝 | 清洁 | 掉毛、灯色发暗 |
| **亲密度** | 长期不理她；老戳她又不管 | 摸头、陪玩、一起完成任务 | 变冷淡，不再主动凑近你 |

### 成长

养到一定程度会长大，一共三段（阶段会真的改变她的行为）：

1. **幼体**：只会张望和打瞌睡，动作少
2. **成长**：多一个伸懒腰
3. **成熟**：加上突然雀跃一下

解锁的是**动作**，不是新的表情素材——脸还是那 57 帧。

### 她不会死

**没有"养死"这回事。** 长期不管，她只会闹脾气——变冷淡、不理你、数值卡在半死不活的位置。
但认真照顾一次就能拉回来。

一台坏掉的桌面设备没有意义，情绪上的疏远比数值死亡更有效。

## 9. 她自己的日常

你不理她的时候，她不会站着不动。

| 行为 | 触发 | 状态 |
| --- | --- | --- |
| 张望 / 环顾 | 长时间闲置 | ✅ 已有 |
| 哼一声 / 自言自语 | 想引起注意 | 🚧 待接入（合成音效引擎已有） |
| 伸懒腰 / 舔爪子 | 随机 | ✅ 已有（动作，无音效） |
| 打瞌睡 → 睡着 | 精力低 | ✅ 已有 |
| 饿了主动叫 | 饱食低 | 🚧 待接入 |
| 亲密度高时主动凑近 | 亲密度高 | 🚧 待接入 |
| 声音 | 喵、雀跃、哈欠、咕噜、咀嚼、叹气（算法现场合成，**不会说话**） | ✅ 已有 |

**她不会聊天。** 没有语音识别、没有大模型、不能回答问题。她只会"有反应"。

## 10. 灯的用法

一颗 RGB 灯，用颜色和呼吸表达状态。

灯用**颜色**说她现在什么心情，用**节奏**说她正在干什么。两者是独立的。

**灯默认是关的。** 它是桌上一颗很亮的 LED，默认亮着会碍事（尤其被 agent 接管时
那串 4 Hz 快闪）。想用就在配网页"显示与灯"里把**指示灯亮度**拉上去，设置会记住；
拉到 0 就彻底关掉。

| 颜色 | 什么时候 |
| --- | --- |
| 暖橙 | 平静、满足（默认） |
| 亮黄 | 开心 |
| 橙红 | 饿 |
| 亮蓝 → 深蓝 | 累 → 困 |
| 青 | 冷淡、长期没人理 |
| 土黄 | 脏 |
| 一点红余烬 | 睡着了（不是全黑） |
| 熄灭 | 夜间模式 |

> 这些颜色是**饱和**的，不是接近白的暖色 —— 早期版本默认色是 `(255,208,160)`，
> 满亮度看就是一颗白灯，谁也分不出情绪。

| 节奏 | 含义 |
| --- | --- |
| 3 秒一次呼吸 | 一切正常 |
| 6 秒一次深呼吸 | 困、累、或冷淡 |
| 一次两下短闪 | **饿**，在提醒你 |
| 4 Hz 快闪 | **电脑上的 agent 正在用她** |
| 常亮 | 睡着（配上面的余烬色） |
| 白色闪两下 | 她**听见你叫她名字**了 |
| 绿色闪一下 | agent 的任务**做完了** |
| 红色闪两下 | agent 的任务**失败了** |

事件闪（白/绿/红）会短暂盖过情绪色，几秒后自己回到原来的呼吸节奏。

灯的**亮度**可以在配网页调（0–100，0 等于关灯），在"显示与灯"那张卡片里，
和屏幕亮度分开写清楚 —— 一个是脸上的屏，一个是机身那颗小灯，互不影响。
调低只改明暗，她的情绪配色不变。

## 12. 和电脑上的 agent 一起用

这是她的第二重身份：**电脑上 AI agent 的身体**。

插上 USB，agent 借她的脸和嗓子；她干活会累，你得伺候她。

### 12.1 怎么连（三步）

| 步骤 | 发生什么 | 她的反应 | 状态 |
| --- | --- | --- | --- |
| 1 | USB 线插上电脑 | 进入"插电态"，**还没交权**，只是打瞌睡 | ✅ 已有 |
| 2 | agent 打开串口，发 `pet.hello` | 灯色和脸交给 agent | ✅ 已有 |
| 3 | agent 断开 / 拔线 / 3 秒没心跳 | 愣一下，回到自主模式 | ✅ 已有 |

**钥匙在 agent 手里。** 插充电器、插充电宝，她只是插着电待机；只有 agent 主动握手，才交出控制权。

agent 还负责两件事：`pet.time` 把时间对给她（她没有 RTC，也没有网络），
`pet.night` 手动让她进/出夜间模式。没对时的话，作息时段不会自动生效。

### 12.2 什么程序能连

| 程序 | 能不能 | 说明 | 状态 |
| --- | --- | --- | --- |
| 任意脚本 | ✅ | 任何能打开串口、按行收发 JSON 的语言（Python、Node、Go…） | ✅ 已有 |
| agent 框架（如 WorkBuddy） | ✅ | 同上，不需要专门适配库 | ✅ 已有 |
| MCP 客户端 | ✅ | 协议就是 MCP 那套 JSON-RPC 格式 | ✅ 已有（行式 JSON-RPC，不是 stdio 传输） |
| 手机 App | ❌ | 不做 | ❌ |
| 浏览器直接连 | ❌ | 需要本地中间层 | ❌ |
| 网络远程控制 | ❌ | 她不联网，没有暴露端口 | ❌ |

**不需要装驱动**，插上就是这个系统里多出来的一个串口。

### 12.3 agent 能让她做什么

| 能力 | 效果 | 限制 | 状态 |
| --- | --- | --- | --- |
| 换表情 | 指定情绪和强度 | 只能选预设的那几组，不能任意画 | ✅ 已有 |
| 说话 | agent 分块推 PCM 过来，她张嘴放 | 有缓冲，不是低延迟对讲；**夜间禁言** | ✅ 已有 |
| 看向某处 / 抬头低头 | 整张脸平移几个像素（**由 agent 或她自己的行为决定**，不是跟着声音转） | 幅度有限（±8 px），屏幕就这么大 | ✅ 已有 |
| 读状态 | 拿到四条数值、模式、成长阶段，以及灯当前的颜色与亮度 | — | ✅ 已有 |
| 上报事件 | 你摸她、她累了、数值变了 | 只推这几类 | ✅ 已有 |
| 代她照顾 | agent 也能喂、清洁、陪玩 | **有上限**：代劳只补一半，且补到 85 就补不动了 | ✅ 已有 |
| 让她睡 / 叫醒 | 强制入睡或唤醒 | 精力见底时叫不醒 | ✅ 已有 |

### 12.4 agent 不能让她做什么

她不是显示器，也不是音箱。这几条是硬边界：

- ❌ 不能任意绘制画面——只能选表情组
- ❌ 不能自定义新动作——只有那套动作原语
- ❌ 不能解锁数值上限、不能删档
- ❌ **夜间不能让她出声**：`pet.say` 也会被拒绝（半夜被提示音吵醒，比漏看一次任务完成更糟）
- ❌ 不能绕过"累了就睡"——精力见底，agent 说什么都没用

最后一条是设计核心：**她的体力约束 agent 的用法**，而不是 agent 无限压榨她。

### 12.5 她会主动告诉 agent 的事

| 事件 | 什么时候 | 状态 |
| --- | --- | --- |
| 被摸了 | `pet.poke`，你按她 | ✅ 已有 |
| 我饿了 | 饱食低于阈值 | ❌ 不做（见下） |
| 我累了 | `pet.tired`，精力低于 15 | ✅ 已有 |
| 我醒了 | 夜间结束 / 被叫醒 | ❌ 不做（见下） |
| 有人吵我 | 夜间被按键或声音惊动 | ❌ 不做（`pet.poke` 已经覆盖） |

> **为什么不加事件**：设备确实会往串口写事件行，但 agent 这一侧的链路是
> "发一条请求、读一条回复"，**主动事件在这一层就被丢掉了**，MCP 客户端也没有通知通道。
> 在没有消费者之前加事件等于白写。agent 想要她的状态，直接读 `pet.status` 就行——
> 一次工具调用，比等推送还快。

### 12.6 你在桌面上看到的样子

| 场景 | 她的表现 | 状态 |
| --- | --- | --- |
| agent 开始干活 | 抬头、东张西望（`pet.face` / `pet.look`） | ✅ 已有 |
| agent 长时间思考 | 抓耳挠腮、东张西望 | 🧩 用法：连着调几次 `pet_face` / `pet_look` 就行，设备不用改 |
| 任务完成 | `pet.task result=done` → 开心动作，精力 −5 | ✅ 已有（无音效） |
| 任务失败 / 被打断 | `pet.task result=error` → 蔫下去，精力 −8 | ✅ 已有（无音效） |
| 连续干了很多活 | 表情越来越蔫 → 直接睡着 | ✅ 已有（精力掉到 30 以下情绪就变"累"，动作变慢、灯转蓝；见底直接睡） |
| 你摸她一下 | 摸头反应，同时 `pet.poke` 推给 agent | ✅ 已有 |
| 她睡着了 agent 还在派活 | 叫不醒，agent 收到明确错误 | ✅ 已有（返回 `-32001 she is asleep…`，不是静默失败） |

### 12.7 插上线的代价

她干活要花体力。agent 用得越凶，你越得伺候她（这几条已经在跑）：

| agent 做了什么 | 她付出什么 |
| --- | --- |
| 完成一次任务 | 精力 −5，亲密度 +2 |
| 报错 / 被打断 | 精力 −8，亲密度 −1，炸毛 |
| 长时间思考 | 精力缓慢下降，表情焦躁 |
| 精力见底 | 强制睡着，拒绝一切请求 |

### 12.8 拔线与独占

**拔线之后**：立刻变回宠物（3 秒没心跳也算断线）。被 agent 弄掉的数值**原样保留**，不会重置——
她记得刚才干了什么。

**独占**：她只有一条串口。当前规则是先到先得，第二个程序要等第一个断开。

> 未决：要不要支持新连接抢占旧连接？以及音频缓冲带来的实际延迟是多少——两者都要真机测试后才能定。

### 12.9 接 DSH（MCP）

如果 agent 是 **DeepSeek Harness（DSH）**，不用写脚本，插件已经做好了：

| 步骤 | 做什么 |
| --- | --- |
| 1 | 仓库里 `dsh/kitty-mcp/` 是一个只有配置的 DSH bundle |
| 2 | 在 DSH 里装它（`plugin_manager install_bundle`，指向这个目录） |
| 3 | 装完立刻多出 **17 个** `mcp__kitty__*` 工具，直接调用 |

工具覆盖全部原语：`pet_status`、`pet_face`、`pet_look`、`pet_attention`、`pet_feed`、
`pet_clean`、`pet_play`、`pet_task`、`pet_sleep`、`pet_wake`、`pet_night`、`pet_volume`、
`pet_time`、`pet_say`、`pet_mic_stats`、`pet_config`、`pet_ping`。

`pet_config` 不在设计稿的原语表里，是为了让 agent 自己能把配网热点叫起来 ——
串口被它占用时，这是唯一不拔线的办法。

背后的 `scripts/pet_mcp.py` 是个 stdio MCP server，它做了一件普通脚本不会做的事：
**开着串口不放，每秒 ping 一次**。所以她会在 agent 连着的时候一直保持"被接管"，
不会每隔 3 秒就掉回自主模式、把 agent 设的表情自己盖掉。DSH 退出后端口关闭，
3 秒内她就回到自己的生活。

## 14. 配网与参数

她不需要连 WiFi 上网。热点只用来改设置，改完就关。

| 步骤 | 操作 | 状态 |
| --- | --- | --- |
| 1 | 长按 BOOT 3 秒，她进入配网模式 | ✅ 已有（单键菜单接入后会改成"长按 → 选配网 → 确认"） |
| 2 | 手机连上她开的热点（Kitty-XXXX / kitty1234） | ✅ 已有 |
| 3 | 浏览器打开 192.168.4.1，改参数 | ✅ 已有 |
| 4 | 保存后热点自动关闭，省电 | ✅ 已有 |

**热点开多久**（WiFi 是整机最耗电的部分，所以它不会一直开着）：

| 什么时候 | 会怎样 |
| --- | --- |
| 刚打开 | 开始倒数 3 分钟 |
| 手机连上 | 倒数重置为 3 分钟 |
| 每打开一次页面、每提交一次表单 | 同样重置为 3 分钟 |
| 点了保存 | **1.5 秒后关闭**，页面先返回成功 |
| 3 分钟没人动 | 关闭，SSID 消失 |

关掉之后射频完全停止：不上网、不扫描、后台也不留热点。配一次网，
射频通常只亮几十秒——这正是设计里不让它常开的原因。

**配置页长什么样：** 一列卡片（她是谁 / 声音与灯 / 脾气 / 作息 / 时间），窄屏满宽、宽屏居中
460 px，底部常驻"保存并关闭热点"。音量亮度用滑块，值直接标在标签行上。

**连上热点会自动跳到配置页。** 她跑了一个"强制门户"：DNS 把任何域名都解析到 192.168.4.1，
所有探测请求（苹果的 captive.apple.com、安卓的 connectivitycheck.gstatic.com、Windows 的
msftconnecttest.com）都回一个 302 指向配置页，所以手机会自己弹出"登录网络"的提示。
个别系统不弹的话，手动打开 `192.168.4.1` 也行 —— 不过屏幕上就不写这串地址了，
只显示热点名和密码，因为正常流程里没人需要手打地址。

### 能改的参数

| 参数 | 说明 | 默认值 | 状态 |
| --- | --- | --- | --- |
| 名字 | 她的名字（存在存档里，界面上用） | Kitty | ✅ 已有 |
| 音量 | 喇叭音量，0–100 | 60 | ✅ 已有 |
| 屏幕亮度 | 脸上那块屏的亮度，0–100，夜间另有单独上限 | 70 | ✅ 已有 |
| 指示灯亮度 | 机身那颗 RGB 小灯的亮度，0–100（**默认 0，也就是关着**），掉电保留 | 0 | ✅ 已有 |
| 唤醒词 | 叫她名字用的**拼音**（中文模型，不能写汉字） | `ni hao xiao mi` | ✅ 已有 |
| 唤醒灵敏度 | 叫名字好不好使：低 / 中 / 高 | 中 | ✅ 已有（直接改检测阈值） |
| 作息时段 | 几点睡、几点起（决定夜间模式） | 23:00–07:00 | ✅ 已有 |
| 性格 | 黏人 / 标准 / 冷淡 / 活泼（改变她自己找事做的频率） | 标准 | ✅ 已有 |
| 难度 | 数值掉得快慢：轻松 / 正常 / 硬核 | 正常 | ✅ 已有 |

> 名字和唤醒词是两件事：名字是显示用的，唤醒词必须是拼音（「你好小咪」→ `ni hao xiao mi`），

## 20. 常见疑问

### 关于联网与云端

**Q：断网了她还能用吗？**
能。她从设计上就不联网，配网热点只是为了改设置。

**Q：云端服务方跑路了呢？**
没有影响。她完全跑在设备本地，没有激活、没有账号、没有远程依赖。

**Q：为什么不做云端大模型对话？**
因为那样一来，服务器一停她就变砖。她的嘴用来叫、不是用来聊天的。

### 关于照顾

**Q：多久要照顾一次？**
取决于难度设置。默认难度下，一两天不理她会明显变冷淡，但不会死。

**Q：她会不会死？**
不会。没有养死机制。长期不管，她只是闹脾气——变冷淡、不理你、数值卡在半死不活。
认真照顾一次就能拉回来。

**Q：能不能开挂/改存档？**
能，数值存在设备里，但说明书不教。

**Q：agent 干活太狠会怎样？**
精力掉光她直接睡着，agent 说什么都没用。这是设计的一部分：她的体力约束 agent 的用法。

### 关于硬件

**Q：能不能只当宠物，不接电脑？**
能，但得插着电——充电器或充电宝都行。插不插电脑都是同一台设备，接电脑只是多一层能力；
这块板没有电池，彻底拔掉电源她就关机。

**Q：她会不会很费电？**
待机功耗、以及夜间连续播呼噜 6–8 小时的功放发热与耗电，目前都还没实测（⏳）。
这是当前最该先测的数。

**Q：屏幕能换成大的吗？**
不能。表情帧是按 88×128 生成的，换屏要重做全部动画。

**Q：为什么只有一颗按键？**
旁边那颗 POWER 是电源开关——按一下断电、再按一下上电，固件读不到它。所以所有操作只能压在 BOOT 一颗键上。

**Q：能不能把 POWER 改成普通按键？**
要改硬件：把它的走线从电源锁存挪到 GPIO。改完之后就得靠别的方式断电。

**Q：能不能加触摸？**
硬件没有触摸屏。要触摸得换屏，等于换一台设备。

**Q：能不能摇晃她？**
没有姿态传感器，摇不动。

**Q：她坏了怎么办？**
先看 §16 故障排查。软件问题重烧固件；硬件问题（不亮、不响、插上没电）得拆。

### 关于开发与升级

**Q：怎么升级固件？**
插 USB 烧录，没有云端 OTA。正常升级不会清掉她的数值，见 §15。

**Q：能装自己的表情包吗？**
不能。表情帧编译在固件里，换表情包要重新生成帧数据并重烧。

**Q：能不能同时接两个 agent？**
不能。只有一条串口，先到先得，第二个要等第一个断开。
